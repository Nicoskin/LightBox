# Замеры: от запуска до фото на экране

Сколько проходит от запуска программы с файлом до момента, когда фото видно на экране. Скрипт: [`tools/bench_open.ps1`](../tools/bench_open.ps1). Замер от 20 октября 2026 года.

## Файлы

Из `cargo run --release --example gen_testdata`, все 6000 × 4000 (24 Мп), один и тот же снимок: небо, холмы, кольца, шум.

| Файл | Формат | Размер |
|---|---|---:|
| `photo_24mp.jpg` | JPEG, качество 92, baseline, 4:2:0, без встроенной миниатюры | 10,1 МБ |
| `photo_24mp.png` | PNG, RGB 8 бит | 28,6 МБ |
| `photo_24mp.tif` | TIFF, RGB 8 бит, без сжатия (скрипт делает его из PNG) | 72,0 МБ |

## Как мерили

1. Перед каждым запуском снимается весь рабочий стол.
2. Программа запускается с файлом, секундомер стартует прямо перед `CreateProcess` (у «Фотографий» — перед `ShellExecute` ссылки `ms-photos:`).
3. Каждые 5 мс ищется самое большое видимое окно программы (по PID, у «Фотографий» — по имени процесса) и снимается центральная часть окна (40 % ширины и высоты), по ней сетка 32 × 32 точки.
4. Фото считается показанным, когда не меньше 60 % точек имеют цвета снимка (небо, земля, кольца) и не были такими на исходном снимке экрана. Засчитывается первый такой опрос, если следующий это подтверждает. Уменьшенная копия считается: это то, что видит пользователь.
5. Процесс завершается, пауза 2 с, следующий прогон.

На каждую пару «программа + файл» — 2 прогона на разогрев, затем 5 замеров; в таблицах медиана и минимум замеров. Файл после разогрева лежит в кэше Windows, так что это «тёплое» открытие, диск почти не влияет.

Точность — около одного кадра: экран обновляется раз в 6 мс (164 Гц), опрос раз в 5 мс, снимок экрана через GDI занимает ещё 1–2 мс.

Окна у программ разные: Lightbox открывается во весь экран (2560 × 1440), IrfanView — по размеру фото (1995 × 1433), «Фотографии» — 1906 × 1052, XnView MP — маленьким окном 852 × 652, ему меньше рисовать.

## Результаты, мс

**Время до фото** — медиана (минимум); «окно» — медиана появления первого окна программы.

| | JPEG | PNG | TIFF | окно |
|---|---:|---:|---:|---:|
| Lightbox, без анимации | **153** (149) | **224** (218) | **148** (146) | 31 |
| Lightbox, по умолчанию | 204 (196) | 297 (280) | 162 (161) | 31 |
| IrfanView 4.76 | 250 (239) | 368 (361) | 202 (188) | 66 |
| XnView MP 1.12.2 | 390 (381) | 512 (502) | 313 (313) | 220–231 |
| Фотографии Windows | 622 (606) | 627 (617) | 610 (600) | 347–362 |

У Lightbox по умолчанию включена анимация открытия: 200 мс, фото вырастает из 82 % размера и проявляется с непрозрачности 35 %. Первый кадр анимации уже с фото, но детектор срабатывает, только когда оно проявилось больше чем наполовину. Поэтому строка «без анимации» (`animations = false` в настройках) точнее показывает, когда фото готово.

## Повторить

```powershell
cargo build --release --target-dir target/bench
cargo run --release --example gen_testdata
winget install --id IrfanSkiljan.IrfanView -e
winget install --id XnSoft.XnViewMP -e
pwsh tools/bench_open.ps1 -Lightbox target\bench\release\lightbox.exe
```

- Отдельная сборка нужна, если Lightbox уже запущен в трее: запущенная копия перехватывает открытие файлов из того же exe.
- XnView MP при первом запуске показывает «Мастер настройки» и ждёт OK. Чтобы пропустить его, создайте `%APPDATA%\XnViewMP\xnview.ini` с секцией `[Start]` и строкой `startupType=0` (настройки текущего пользователя) — или один раз нажмите OK вручную.
- Скрипт ждёт, пока экран разблокирован, мышь и клавиатура не трогались 60 с и не запущена полноэкранная программа или игра. При любом вводе он останавливается и завершает просмотрщик; `-Resume` продолжает с того же места. Сырые результаты — в `target\bench_open.csv`, `-SnapDir` сохраняет снимки окон для проверки.
